## 2024-04-24 - Fix Insecure Random Number Generation for IDs

**Vulnerability:** The application was using `Math.random()` to generate Order IDs and Transaction IDs on the frontend (`components/PaymentsScreen.tsx`). `Math.random()` is not cryptographically secure, leading to predictable identifiers. Additionally, the generation logic was directly within the render function, meaning IDs would regenerate and change visually every time the component re-rendered (e.g., when a loading state toggled).
**Learning:** In React components, generating sensitive or semi-sensitive identifiers using `Math.random()` during render is a double failure: it is cryptographically weak, and it creates unstable UI states due to React's rendering lifecycle. Using `crypto.randomUUID()` provides security, and wrapping it in a `useState` lazy initializer `useState(() => crypto.randomUUID()...)` ensures the generated value remains stable across re-renders.
**Prevention:** Always use the Web Crypto API (`crypto.randomUUID()` or `crypto.getRandomValues()`) for generating unpredictable tokens or identifiers. When these values are generated client-side in a React component, they must be preserved across renders, typically by using a lazy initializer in `useState` or a `useRef`, depending on whether the value's generation should trigger a render.
