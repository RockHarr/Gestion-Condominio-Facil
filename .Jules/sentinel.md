## 2025-01-03 - Context-Aware URL Sanitization for Images
**Vulnerability:** XSS and malicious protocol loading via `<img>` tags. Unsanitized or broadly sanitized (allowing `data:text/html`) image sources could allow arbitrary code execution or unexpected browser behaviors if user-controlled input (like ticket attachments or amenity photos) includes malicious protocols (like `javascript:`).
**Learning:** Generic URL sanitizers used for both `href` and `src` attributes are problematic. The existing `getSafeUrl` didn't allow `data:`, which might be needed for some legitimate inline images. However, simply adding `data:` to a global allowlist could be dangerous for `href` attributes (allowing `data:text/html`). Therefore, a context-aware sanitizer specifically for images (`getSafeImageUrl`) is needed to safely allow `data:` while blocking it elsewhere.
**Prevention:** Implement context-aware URL sanitization. Use specialized sanitizers (e.g., `getSafeImageUrl`) for `src` attributes that specifically allow image-related protocols (including `data:`) while blocking them for generic `href` links to maintain defense-in-depth against XSS.
